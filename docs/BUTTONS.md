# Кнопки TextTools: схема и правило «функция ↔ кнопка»

Зачем этот файл: случались кнопки, которых нет на экране или не видно.
customtkinter и Tk молча кладут вторую кнопку поверх первой,
`winfo_ismapped()` при этом возвращает True, клик-тесты проходят —
а пользователь кнопку не видит. Поэтому три вещи: живая схема ниже
(генерируется из кода, не пишется руками), геометрический аудит
`test_gui_buttons.py` и обязательное правило при любой правке функций.

## Правило «функция ↔ кнопка» (обязательный проход)

Каждый пункт делается при добавлении или изменении функции, у которой
есть хоть какой-то след в интерфейсе. Пропуск любого пункта — тот же
баг, что и неработающий код.

1. **Место.** Кнопка живёт на вкладке, в карточке родственных действий.
   Текст — глагол («Найти», «Почистить», «Заменить»), не «ОК».
2. **Начинка.** `command` зовёт существующий движок, а не заглушку.
   Tooltip: что делает, что пишет на диск, где бэкап. Вид по семантике:
   спокойная — обычное действие (по умолчанию dry-run); фиолетовая —
   ключевое действие; красная — реальная запись; синяя рамка со «▸» —
   открывает окно/список. Селектор обязан иметь значения
   и обработчик; галочка — подпись и дефолт из конфига.
3. **Регистрация в клик-тесте.** Новую кнопку вписать в `test_gui.py`:
   `RUN_BUTTONS` (клик с подменой движка), `UTILITY_BUTTONS` или
   `SKIP_BUTTONS` (с комментарием, почему не кликается).
4. **Аудит геометрии.** `python test_gui_buttons.py` — ловит кнопку,
   которой нет на экране: не упакована (manager пуст), лежит поверх
   другой, обрезана справа, без command, селектор без значений.
   Потом `python test_gui.py` (клики) и `python test_gui_fit.py`
   (умещение рядов при масштабах 1.0 и 1.25).
5. **Схема.** `python test_gui_buttons.py --fix-docs` — обновить схему
   ниже между маркерами, закоммитить вместе с фичей. Расхождение схемы
   с кодом — провал проверки, а не «мелочь в доке».
6. **Доки по месту.** GUI_GUIDE.md — кнопка и сценарий; MANUAL.md —
   CLI-эквивалент; README.md — если у команды появился новый флаг.

## Как читать схему

Три таблицы на карточку — кнопки (тип = цветовая семантика), галочки
и селекторы. «—» вместо действия значит служебный элемент без
подсказки (выбор файла «…», история «▾», «Файл»). Порядок строк =
порядок создания, то есть фактический порядок на экране сверху вниз.
Обновляется только скриптом; правки руками сотрутся при следующей
генерации.
