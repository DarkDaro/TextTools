# BACKLOG — предложения на согласование

Статус: **на согласование** (05.11.2026). В работу ничего не берётся
без одобрения; каждый принятый пункт — отдельный чанк с тестами и
правками доков.

Формат: что / зачем / как / цена (S — до часа, M — вечер, L — больше).
Порядок — моя рекомендация, решение за автором.

---

## 1. CLI-команда `yo` — паритет GUI и CLI [S]

**Что.** Ё/Е-аудит доступен из GUI и прямым вызовом
`python tools/yo_audit.py`, но в `textools.py` подкоманды нет (24-я
команда). Добавить `yo` с флагами `--registry`, `--dict`, `--review`,
`--limit`, `--out` — проводка по образцу соседних веток.

**Зачем.** Скриптовые прогоны и привычка «всё через textools.py»;
сейчас команду не найти по `textools.py --help`.

## 2. «Репетиция чистки» — общий план правок [M]

**Что.** `check-all --plan план.md`: поверх шести проверок собрать
человекочитаемый план стилистической правки — штампы (фраза → замена,
файл, сколько раз) и hard-вхождения АНТИРЕШИМОСТЬ (что будет вырезано,
файл), с итоговыми счётчиками.

**Зачем.** Пишущие инструменты (чистка штампов, зачистка) запускаются
по одному и вслепую. Один план до запуска = писатель видит весь объём
и порядок работы, ничего не правится.

**Как.** Данные уже собираются в check-all (скан-режимы); нужна только
компоновка в md через `core.report.write_report`.

## 3. Динамика объёма — дневник писателя [S]

**Что.** `stats --history`: читать уже существующий
`reports/stats_log.csv` (его пишет `stats --csv`) и печатать/выводить
в отчёт прогресс по датам: слова, диалоги, дельта с прошлой записью,
средняя скорость в день.

**Зачем.** Дневник объёма уже копится, но посмотреть на него можно
только в Excel. Мотивация автора — «за неделю +6 400 слов, темп 900/день».

## 4. Экспорт главы `.md` → `.docx` [M]

**Что.** Новая подкоманда `export-docx`: заметка/папка Obsidian →
Word-файл (заголовки `#` → стили Heading, абзацы, диалоги; ё-словарь
и типографика — опционально на выходе).

**Зачем.** Бета-ридеры и редакторы живут в Word; сейчас путь
«md → docx» вручную. Обратная задача (чтение docx) уже решена.

**Как.** python-docx умеет создавать документы; риски — соответствие
стилей и кавычек; делать с осторожным минимумом (без «улучшений»).

## 5. Человекочитаемая сводка check-all в файл [S]

**Что.** `check-all --out отчёт.md`: md-версия сводки шести проверок
(сейчас человеческий вывод только в консоль, в файл — только JSON).

**Зачем.** Журнал проекта: приложить к папке главы отчёт «проверено
тогда-то, найдено то-то». Данные все есть, нужна компоновка.

## 6. Межглавные повторы — «эхо-фразы» [M/L]

**Что.** Новый скан: конструкции, повторяющиеся между РАЗНЫМИ файлами
(«мир сжался», «задышал ровнее»), с порогом частоты и исключением имён
реестра. Внутри файла повторы ловит `style-report`, между файлами —
никто. Механику шинглов можно переиспользовать у merge_finder.

**Зачем.** Главный стилистический грех длинной рукописи — повтор
приёма через главу; по одиночным файлам он невидим.

**Риски.** Шум: нужен настраиваемый порог, белый список (имена,
термины) и аккуратная подача (топ-N, не «ошибки»).
