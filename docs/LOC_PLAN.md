# Пайплайн поддержки английского языка

План превращения TextTools из русскоязычной утилиты в двуязычную.
Заведён 18.11.2026. Главный принцип: интерфейс
уже спроектирован и заново не рисуется — меняются только строки;
тексты обрабатываются по правилам выбранного языка.

## Две оси

Языка два, и это два независимых ключа конфига:

* `text_lang` — язык текстов («ru»/«en»): по каким правилам работают
  скрипты. Стоп-листы, слова-паразиты, словари штампов, детект
  диалогов, поиск имён;
* `ui_lang` — язык интерфейса («ru»/«en»): какие строки видит человек
  в окне. Разметка, вкладки, кнопки, горячие клавиши — без изменений.

Откуда инструменты берут язык (первый источник выигрывает):

1. флаг `--lang ru|en` в командной строке;
2. переменная окружения `TEXTOOLS_LANG` — для тестов и CI;
3. ключ `text_lang` (или `ui_lang`) из `gui_config.json`;
4. по умолчанию «ru» — поведение версии 1.8.4 ни для кого не меняется.

Единая точка чтения — `core/lang.py` (функция `get_text_lang` /
`get_ui_lang`). GUI запускает инструменты как подпроцессы, поэтому
выбор на «Настройках» доезжает и до кнопок, и до CLI без всякой
передачи аргументов: обе стороны читают один и тот же ключ конфига.

## Правило словарей

Русский словарь называется как раньше, английский — с суффиксом `_en`:

| Русский | Английский |
|---|---|
| tools/parasites.yaml | tools/parasites_en.yaml |
| data/resolve_db.yaml | data/resolve_db_en.yaml |
| data/pathos_db.yaml | data/pathos_db_en.yaml |

Файл `_en` необязателен: нет файла — работают встроенные английские
списки (как и у русского: нет yaml — встроенный список). Свои
свои правки вносятся в те же файлы, руками..

## Разбор инструментов: что зависит от языка

| Группа | Инструменты | Судьба |
|---|---|---|
| Правила не зависят от языка | whitespace, separators, integrity, utf8, cjk, obsidian-check, broken-links, orphan-finder, merge-finder, moc, export-docx | ничего не делать — уже работают с любым текстом |
| Стоп-листы и счётчики | registry-builder, cast, matrix, consistency, style-report, echo, stats | стоп-слова, паразиты, детект диалогов и служебные слова — по языку (этап 2) |
| Словарные инструменты | antiresolve | англ. словари resolve_db_en.yaml / pathos_db_en.yaml, флаг --lang (этап 3) |
| Русская специфика | yo (буква ё) | на англ. тексте честно не находит ничего — так и оставить |
| Типографика | typography | кавычки правит только вокруг кириллицы, для англ. текста безопасна; англ. нормы кавычек («”) — отдельный заход, если понадобится |
| Штампы-фразы | phrase-check | словарь задаётся флагом --dict, англ. словарь подключается тем же флагом |

Генерация имён (вкладка «Имена персонажей») — данные, не код:
английские источники имён подключаются отдельным заходом после
этого плана.

## Этапы

1. **План** (этот файл) — сразу коммитом.
2. **Ядро языка**: core/lang.py + англ. стоп-лист в text_parser
   (STOPLIST_RU / STOPLIST_EN / stoplist(lang)); параметр lang у
   find_name_candidates и find_bigrams.
3. **Аналитические инструменты**: registry_builder, cast_list,
   style_report, text_stats, echo_finder — англ. служебные слова,
   англ. паразиты, диалоги в кавычках («"Hello," she said»), все
   принимают lang / --lang.
4. **Словари-стартеры**: resolve_db_en.yaml и pathos_db_en.yaml —
   английская версия «антирешимости» и антипафоса; у antiresolve
   появляется --lang.
5. **Настройки**: вкладка «Настройки», раздел «Язык» — два
   переключателя (Язык текстов, Язык интерфейса), оба пишут
   gui_config.json; gui_config.example.json обновляется.
6. **i18n-инфраструктура**: core/i18n.py — словарь STRINGS
   (ключ → {ru, en}) и tr(); строка переводится только через словарь.
7. **Перевод вкладок** — последующие заходы, по правилу «вкладка =
   коммит = её GUI-тест»: Настройки → Помодоро → Чистка → Замены →
   Хранилище → Имена персонажей → Писателям → Журнал → шапка, тосты,
   диалоги. Разметку не трогаем — подменяются только тексты.
8. **Доки**: MANUAL и GUI_GUIDE остаются русскими до отдельной
   просьбы; README.en уже есть и обновляется в релизном коммите.
   Скриншоты не переснимаются (правило 18.11: без просьбы).

## Границы плана

* Автоопределение языка текста (кириллица/латиница) — кандидат в
  BACKLOG, не делается сейчас: явный выбор надёжнее и предсказуемее.
* Отчёты, логи и подсказки инструментов остаются русскими — это
  язык редактора-человека; вопрос их перевода ставится отдельно.
* Машинного перевода словарей нет: каждый англ. словарь —
  выверенный список, как и русский.

## Когда считать готовым

* При text_lang=en все аналитические команды дают осмысленный
  результат на английском тексте: паразиты, повторы, эхо, имена,
  штампы ищутся по английским правилам.
* В «Настройках» два переключателя, выбор живёт в gui_config.json
  и переживает перезапуск.
* Интерфейс переведён вкладка за вкладкой без перерисовки, каждая
  вкладка проходит свой тест.
