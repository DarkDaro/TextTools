# Техдолги TextTools

Живой список технических долгов проекта. Это не список ошибок — это
список осознанных упрощений, отложенных работ и границ, о которых
нельзя забывать. Ведётся с 18.11.2026.

Правила ведения:

* один пункт — одна проблема;
* пункт заводится сразу, как замечено, — даже если чинить не
  планируется: незаписанный долг перестаёт существовать и всплывает
  в самый неподходящий момент;
* при исправлении статус меняется на `закрыт`, в конце пункта —
  дата и версия (или коммит), где закрыто;
* закрытые пункты не удаляются: они остаются как память о том,
  почему всё устроено именно так;
* раз в релиз список перечитывается целиком: что потеряло смысл —
  вычёркивается.

Статусы: `открыт`, `в работе`, `закрыт`, `ждёт решения`.

## TD-01 — Тестовые материалы `external/emoji-cleaner/` (закрыт 21.11.2026)

**Суть.** В папке внешнего скрипта `external/emoji-cleaner/` рядом
с рабочим `clean.py` лежат тестовые материалы отладки: `_test*.py`,
`_verify.py`, `test*.md/txt`, `bin.txt`, `ta.md`.

**История.** 21.11 вычищены коммитом как мусор — владелец попросил
вернуть («эмоджи клинер то верни только... я потом посмотрю что там
удалил а что осталось»). Файлы возвращены revert-коммитом, статус
закрыт: решение владельца — оставить.

**Взамен.** По той же просьбе клинер получил режимы против следов
ИИ: `--invisible` (невидимые символы, теги-водяные знаки), `--ws`
(табы и необычные пробелы), `--ai-scan` (только чтение: следы ИИ,
подмена алфавита, скрытый/белый текст в docx) — и те же режимы на
вкладке «Чистка».

## TD-02 — Визуальный QA GUI выполняется руками (закрыт 21.11.2026)

**Суть.** Приёмка интерфейса — скриншоты всех вкладок в двух темах
при масштабах 1.0 и 1.25, в окнах 1280x800 и 980x640 — выполняется
вручную под Xvfb. В 1.8.1 такая приёмка проведена и нашла девять
мест с обрезанными подсказками и три широких ряда кнопок, но
сам процесс не автоматизирован: при следующем редизайне всё
повторяется руками.

**Чем мешает.** Медленно и неустойчиво к рассеянности: легко
прогнать не все темы/масштабы. Автоматический `test_gui_fit`
проверяет умещение рядов кнопок, но не паддинги, не обрезание
подсказок и не внешний вид.

**Как закрыто.** tools/qa_shots.py: сам открывает окно в темах
light/dark и масштабах 1.0/1.25, снимает вкладки в PNG
(`reports/screenshots/`, в git не входит), помечает подозрительно
пустые кадры (меньше 15 уникальных цветов) и печатает чек-лист для
просмотра человеком. Проверен вживую под Xvfb: снимки 1280x800 в двух
масштабах, файлы создаются, конфиг восстанавливается. Просмотр
подсказок/паддингов остаётся за человеком — по правилу проекта
скриншоты без просьбы владельца не снимаются.

## TD-03 — Нет CI: тесты гоняются только вручную (закрыт 21.11.2026)

**Суть.** Ядро pytest (209 тестов) и GUI-скрипты запускаются руками
на машине автора. GitHub Actions не подключён: коммит с поломанным
ядром может доехать до GitHub до первого локального прогона.

**Чем мешает.** Ошибки вылавливаются на шаге регрессии, но этот шаг
существует только в дисциплине разработчика — CI ловит и то, что
забыто.

**Как закрыто.** `.github/workflows/run-tests.yml`: триггеры push
и PR в main, матрица Python 3.10–3.13, шаги — установка зависимостей
и `python -m pytest test/ -q` (ядро без GUI — дисплей не нужен).
GUI-скрипты остаются локальными, как и решено. Заодно закрыт мелкий
хвост: удалён мусорный файл «-» в корне (случайно записанный отчёт),
на него падали два теста stdout-отчётов.

## TD-04 — Смоук-прогон всех CLI-подкоманд (закрыт 21.11.2026)

**Как закрыто.** tools/cli_smoke.py, команда `python textools.py
smoke` (повышение рабочего скрипта polygon_run.py). Read-only команды
идут по полигону test/demo_garbage/vault, пишущие — по временной
копии; сводка «команда → код → время → ключевые строки». Вердикт:
0 — ок, 1 — штатные находки, 2+ или Traceback — ПРОВАЛ; smoke
возвращает код 1, если были провалы. update пропускается намеренно
(единственная сетевая команда). В GUI — кнопка «Проверка команд
(смоук)» на «Настройках». Живой прогон 21.11: все 34 подкоманды
отработали штатно за ~13 секунд.

## TD-05 — doctor не проверяет «живое» приложение целиком (закрыт 21.11.2026)

**Суть.** `doctor` проверяет файлы, словари, зависимости, внешние
скрипты и согласованность версий, но не проверяет работу: окно не
открывает, патник и ярлыки не трогает. Речь о самопроверке
приложения целиком — «запустился, отрисовался, закрылся».

**Чем мешает.** Ситуация «файлы на месте, а программа не открывается»
(битый Python, слетевший customtkinter) диагностируется пользователем
вслепую.

**Как закрыто.** `python textools.py doctor --gui`: gui_ctk.pyw
запускается с `--selftest`, окно строится, отрисовывается и
закрывается само; selftest печатает одну JSON-строку (версия,
customtkinter, вкладки). doctor сверяет версию окна с версией ядра и
число вкладок (8) и сообщает конкретно: «окно не отстроилось за N с»,
«версия окна ... не равна версии ядра ...», «вкладок N, ожидалось 8».
В журнале самопроверка не мусорит. 8 юнит-тестов (разбор диагностики
без дисплея + живой прогон при DISPLAY).

## TD-06 — Запускатели и патник только под Windows (открыт)

**Суть.** `textools_gui.bat`, `update.bat` и `tools/*.ps1` — Windows.
Код ядра и GUI (customtkinter) кроссплатформенен сам по себе, но
запускается с Windows-машины только через эти файлы.

**Чем мешает.** Ничего: README честно говорит «не для macOS и Linux»,
это осознанная граница проекта, а не недоделка.

**План.** Не планируется. Пункт ведётся, чтобы границу не потерять
из виду: если когда-нибудь понадобится Linux — начинать придётся
отсюда.

## TD-07 — `archive/` хранит набор под прежний интерфейс (закрыт 21.11.2026)

**Суть.** В `archive/` лежит старый синтетический набор
(`test_engines.py` и данные), написанный под прежний интерфейс.
Из pytest исключён (`norecursedirs`), гоняется вручную из своей
папки.

**Чем мешает.** Вес репозитория и ложный след: читатель может
подумать, что набор актуален. `archive/README.md` объясняет статус,
но сам код давно не прогонялся и может просто не работать.

**Как закрыто.** Ужато до заметки: из git вычищены 324 файла
случайных прогонов (`_junk/`, `_tmp_*`, `backups/`, `_stub_*`,
`test_history_tmp.py`) и сгенерированный `corpus/` (пересоздаётся
при запуске). Остались `README.md` со статусом «история» и три файла
набора (`gen_corpus.py`, `test_engines.py`, `test_gui.py`).

## TD-08 — `find_cjk.py` в корне проекта (закрыт 21.11.2026)

**Суть.** Поиск иероглифов и мойбейка — функционально ядро (CLI
`cjk`, карточка на вкладке «Хранилище»), но файл лежит в корне рядом
с `textools.py`, а не в `core/`, где остальные движки.

**Чем мешает.** Корень захламляется; новичок ищет движки в двух
местах.

**Как закрыто.** Перенесён отдельным коммитом: `core/find_cjk.py`;
обновлены импорты в textools.py, gui_ctk.pyw (paths и tool-run),
tabs_vault.py, tools/full_check.py, tools/app_check.py,
test/test_cjk_docx.py, test/test_json_reports.py, pyproject.toml
(пакет core уже включён), sys.path-костыль в самом модуле теперь
ведёт в корень проекта. CLI `cjk`, GUI-карточка и все тесты зелёные.

## TD-09 — Поле About на GitHub пустое (закрыт 21.11.2026)

**Суть.** У репозитория не заполнено описание в поле About (description
и topics): PATCH через API вернул 403 — у fine-grained токена владельца
нет разрешения Administration (пуш оно даёт, метаданные репозитория —
нет).

**Чем мешает.** Витрина репо выглядит безымянной: без описания и
топиков репозиторий не находится ни поиском GitHub, ни по темам.

**Как закрыто (21.11.2026).** Поле заполнено владельцем вручную:
описание на русском («Настольные инструменты для анализа и обработки
текстов: Obsidian, реестр персонажей, чистка, массовые замены.
Windows, Python 3.1x») и 10 топиков (cli, customtkinter, desktop-app,
markdown, obsidian, python, russian, text-processing, text-tools,
writing). Попытка правки через API 21.11 вернула 403 — у токена нет
права Administration; поле не тронуто, править не потребовалось.
Заготовленный английский текст остаётся тут на память:

* description: `Offline writing toolkit for fiction: character-name
  consistency, typography, cliché cleanup, vault integrity. CLI + GUI.
  No AI, no cloud.`
* topics: `python`, `cli`, `gui`, `customtkinter`, `obsidian`,
  `writing`, `text-processing`, `typography`, `offline`, `writers`

**На будущее.** Если захочется сменить описание или топики: либо
выдать токену право Administration: Read and write (Settings →
Developer settings → Fine-grained tokens), либо править через
шестерёнку About на странице репозитория.

## Как заводить новый пункт

1. Свободный ID: `TD-XX`, следующий за максимальным.
2. Строка в таблице «Сводка» и раздел с тем же ID ниже.
3. В разделе: суть, чем мешает, план (или «не планируется» — с
   причиной).
4. Коммит со словами `docs: техдолг TD-XX — <кратко>`.
